Show all six installation steps
  1. Download the HTMLUse the file on the left, or extract it from the Dataverse ZIP.
  2. Create a web resourceGo to Power Apps → Solutions → your unmanaged solution → New → More → Web resource. Choose Webpage (HTML), upload the file and save.
  3. Publish the web resourceCheck its full name after saving and select Publish. Your publisher's customization prefix is added automatically.
  4. Add it to your model-driven appOpen the app designer → Pages → New → Web resource, and select the FetchFlow web resource.
  5. Show it in navigationKeep Show in navigation selected and give the page a title such as FetchXML Builder.
  6. Save, publish and testOpen the model-driven app, select FetchXML Builder, discover tables and run a read-only query as the signed-in user. Use the Explorer below for offline analysis.
Live Dataverse access: The installed Builder reads table, column and relationship metadata and runs read-only FetchXML using the signed-in user's permissions. Results may contain sensitive records; preview is capped at 50 rows. The separate Explorer works offline without a Dataverse connection. Nothing is automatically saved or sent to Mightora.

      Three different perspectives
      The diagrams deliberately answer different questions about the same FetchXML.
      

      01 · Where the data comes from
      Source tables, aliases, relationship keys and join types.
      Follow the arrows from the primary table. An inner join requires a match; an outer join can preserve primary rows when no related record exists.
      

      02 · How the query works
      A conceptual flow showing source, joins, filters, aggregate work, sorting and output.
      This is an explanatory sequence, not Dataverse's optimised physical query plan. Exact execution order and cost cannot be inferred from XML alone.

      Network transparency
      All FetchXML parsing, diagram creation, SVG / PNG / JSON / Mermaid exports and office document creation happen in your browser.         Verify independently: press F12 → Developer Tools → Network → enable Preserve log → reload and inspect requests. Browser resource timing may omit some requests and is not a security audit.
        What this tool does not do
        It does not run your query, connect to Microsoft Dataverse, access real records, validate security roles or confirm underlying relationship metadata. Join semantics and filter application are explained conceptually; query optimisation, actual row counts, dynamic lookups and cost are not measured.
        Filters involving entityname can apply after a join. Special semi-join link types may behave differently from ordinary joins. Check the Microsoft documentation for production-critical decisions.

        Frequently asked questions
        What is FetchXML in Power Platform?
        FetchXML is an XML-based query language used in Dataverse and model-driven Power Apps. It describes which table to read, which columns to return, filters, relationships, ordering, and optional aggregation.
        Can I add FetchFlow as a full page within a model-driven app?
        Yes. Use the on-page installation guide to download the HTML web resource, upload it to an unmanaged solution, then add a Web resource page in the model-driven app designer. It appears within the app navigation with a compact Mightora header and the full query-building workspace. Optional form and command-bar launchers are also included. Within a signed-in model-driven app, the Builder reads metadata, executes read-only FetchXML and visualises the query on demand. The separate public Explorer does not connect to Dataverse.
        Does this run queries against my environment?
        No. It builds diagrams from the XML structure only. You do not provide an environment URL or credentials.
        Can I edit the exported PowerPoint diagrams?
        Yes. PowerPoint diagrams are made from regular text boxes, connectors and shapes, not embedded screenshots.
        Is the Word export editable too?
        Yes. Word contains editable text and native tables for the data-source, query-flow and field-lineage diagrams. The layout is table-based rather than PowerPoint-style free-floating shapes.
        How are from and to interpreted?
        In a link-entity, from is the related table column and to is the matching parent table column. The visualisation labels this relationship explicitly.
        Does it work without the internet?
        Yes. Download the dedicated offline HTML or ZIP; the offline release embeds its JavaScript, styling and branding. Developer tools can verify that it makes no application network requests.
